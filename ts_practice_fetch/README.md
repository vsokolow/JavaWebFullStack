# Каталог товаров — практика fetch + TypeScript

Мини-проект на чистом TypeScript, без фреймворков.
API: [dummyjson.com/docs/products](https://dummyjson.com/docs/products), ключ не нужен.

## Запуск

```bash
npm install
npm run dev
```

Открыть http://localhost:5173

Проверить типы отдельно: `npx tsc --noEmit`

## Что уже готово

Вёрстка, стили, работа с DOM, обработка ошибок и все типы. Трогать не нужно —
время занятия уходит на запросы и типизацию, а не на `createElement`.

## Что делаете вы

Шесть заданий, помечены в коде как `// TODO`. Идти строго по порядку:
после каждого задания страница работает чуть лучше, чем до него.

| № | Файл | Что делаем | Тема TypeScript |
|---|------|-----------|-----------------|
| 1 | `src/api.ts` | `toProduct` — маппинг модели API в свою | зачем две модели вместо одной |
| 2 | `src/api.ts` | `fetchProducts` — загрузить список | `async/await`, `Promise<T>`, `response.ok` |
| 3 | `src/api.ts` | `fetchByCategory` — фильтр по категории | union-тип `Category` |
| 4 | `src/main.ts` | `filterByQuery` — поиск по названию | типизированный `filter`, `Product[]` |
| 5 | `src/api.ts` + `src/main.ts` | `fetchProductById` + `showDetails` | ответ без «конверта», `try/catch` |
| 6* | `src/types.ts` | тип `CartItem` | `Pick`, `Omit` |

Задание 6 — со звёздочкой, если останется время.

До первого выполненного задания страница показывает красным
«Задание 2 не выполнено». Это нормально: заглушки специально бросают
исключение, чтобы было видно, что именно ещё не написано.

## Порядок файлов при чтении

1. `src/types.ts` — прочитать целиком до начала работы. Там все типы с пояснениями.
2. `src/api.ts` — задания 1, 2, 3, 5.
3. `src/main.ts` — задания 4 и 5.

## Три вещи, ради которых всё это

**Ответ приходит в «конверте».** dummyjson отдаёт не массив, а объект
`{ products, total, skip, limit }`. Отсюда дженерик `ApiListResponse<T>`.
А вот `/products/{id}` возвращает товар напрямую, без конверта — на этом
специально можно споткнуться в задании 5.

**`fetch` не бросает исключение на 404 и 500.** Он спокойно возвращает
ответ, и без проверки `response.ok` вы будете разбирать страницу ошибки
как будто это товары.

**`response.json()` возвращает `any`.** Мы пишем `as ApiListResponse<ApiProduct>` —
это обещание компилятору, а не проверка. Если API изменится, TypeScript
промолчит, а приложение сломается в рантайме. Хороший повод поговорить
про runtime-валидацию.
